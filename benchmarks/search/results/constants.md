# Canonical Constants and Separation Proof

Generated by `tools/gen_constants.py`. `eps` is parsed as an exact
decimal fraction, scaled by `2^64` with `fractions.Fraction` and
arbitrary-precision integers, and rounded with an explicit
round-to-nearest-even. No `double` intermediate appears anywhere in
the derivation and no `double` representation of `2^64` is built.

## Parameters

```text
N   = 100003     prime -> 100002 candidates, all coprime to N
T   = 1000       steps per candidate (1.00002e+08 inner iterations total)
eps = 21/2000      exact decimal 0.0105
```

## Precondition 1 - `T` is not a multiple of `N`

`x_t = ((t*z) mod N)/N`. Because `gcd(z,N)=1`, multiplication by `z`
permutes the residues mod `N`, so over a full period `t = 1..N` every
candidate visits every residue exactly once and `hits` would take the
same value for every `z`. With `T = 1000 << N = 100003` each candidate
visits a `z`-dependent subset and `hits` genuinely discriminates.

```text
T % N = 1000   (non-zero, asserted)      T < N: yes
```

## Precondition 2 - `eps*N` is not an integer

Reachable points are exactly `k/N`. If `eps*N` were integral a
reachable point would land precisely on a window edge and FP drift,
FX64 rounding and exact integer arithmetic could disagree about which
side it falls on. The exact closest approach of any reachable point to
either edge is `min_k |k*Q - E*N| / (N*Q)`, with `E = P` for the lower
edge and `E = Q-P` for the upper.

```text
eps*N                   = 2100063/2000 = 1050.0315   (not an integer)
min_k |k*Q - P*N|       = 63           (lower edge, eps)
min_k |k*Q - (Q-P)*N|   = 63           (upper edge, 1-eps)
edge clearance          = 63/200006000 = 3.149906e-07

FP   drift bound        = 2*T*2^-53 = 2.220446e-13
FX64 drift bound        =   T*2^-65 = 2.710505e-17
safety ratio (FP)       = 1.418591e+06    (asserted > 1e5)
safety ratio (FX64)     = 1.162110e+10    (asserted > 1e5)
```

The FP bound charges `2^-53` to the rounding of `alpha = fl(z/N)` and
`2^-53` to each of the `T` additions; the conditional `- 1.0` is exact
because it cancels within a single binade. No reachable point comes
within six orders of magnitude of an edge, so FP, FX64 and the exact
integer reference are *forced* to identical `hits` for every candidate.

Also `k = (t*z) mod N` is never 0 for `1 <= t <= 1000 < N` with `N`
prime and `gcd(z,N)=1`, so there is no `x = 0` edge case.
